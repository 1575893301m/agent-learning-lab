# 运行结果与问题记录

## 故障时间线

### 问题 0：Ollama 返回 HTTP 502

- **现象：**第一次运行在 `ollama.chat()` 处报 502，还没有开始文件操作。
- **当时判断：**Python 请求本地 Ollama 服务时受地址/代理环境影响。
- **处理：**在当前 PowerShell 设置 `OLLAMA_HOST=http://127.0.0.1:11434`、`NO_PROXY/no_proxy=127.0.0.1,localhost`，并移除当前会话的 HTTP(S)/ALL proxy 后验证连接。
- **结果：**后续运行成功收到模型回复，连接问题与 Agent 流程问题分开处理。

### 问题 1：模型跳过列文件/读取，并把原文直接当总结

- **现象：**模型从 `filter_paragraphs` 直接跳到 `write_summary`，没有先列出和读取文件；最终回答把原文当总结。
- **当时思路与处理：**在 Harness 中增加流程状态检查，要求按 list/read/filter/write 顺序，并要求写入后才能结束。
- **结果：**没有彻底解决。检查失败后仍把下一步决策交给模型，错误循环仍可能持续。

### 问题 2：模型一次输出多个 JSON Action

- **现象：**同一回复连续包含多个 Action，甚至添加未定义的 `action_id`，解析失败或被参数校验拒绝。
- **当时思路与处理：**启用 Ollama `format="json"`、加强“每轮一个 Action”的提示，并把 `MAX_STEPS` 从 8 提高到 16。
- **结果：**仍未彻底解决。JSON 模式只约束语法，不保证工具选择、调用顺序或参数正确；增加步数只是延长失败循环。

### 问题 3：模型反复跳步并提交空总结，耗尽最大步数

- **现象：**轨迹反复出现 `list_files`、跳过 `read_file` 的 `filter_paragraphs`、`content: ""` 的 `write_summary`，最终返回“超过最大步骤限制”。
- **原因复盘：**程序虽能拒绝错误 Action，却把恢复规划继续交给同一个小模型；每次失败都消耗一步。状态检查是“拒绝错误”，不是“可靠推进正确步骤”。
- **最终处理：**重构 Harness。Python 固定执行 list → 每个文件 read → filter，收集全部命中段落；模型只生成摘要文本；Python 校验摘要非空并写入。模型不再生成工具 JSON，因此不能跳步、批量调用或提交空的写入参数。
- **当前状态：**Harness 已重构，语法检查通过，自动化测试 6 项全部通过；用户本机端到端运行成功，筛出 3 个段落并生成总结文件。
